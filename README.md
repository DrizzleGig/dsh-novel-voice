# dsh-novel-voice

**排字房：导入你喜欢的小说，学习写法；写前给 AI 文风简报，写后定位 AI 味，只修改命中的句子。**

让 AI 学会你喜欢的表达方式，也让自己的写作习惯逐渐沉淀成可复用的文风档案。

## 快速开始

从 npm 安装：

```bash
npm install dsh-novel-voice
```

安装后，在 DSH 对话中启用：

```text
/voice on
```

排字房默认关闭，不会自行介入写作。

基本使用方式：

1. **导入作品**：导入喜欢的小说和自己的作品，按章节整理并学习写法。
2. **建立文风档案**：从作品中提取文体特征，形成可复用的风格记录。
3. **写前获取简报**：生成文风简报，供 AI 在写作时参考。
4. **写后检查**：定位正文中可能存在的 AI 味，具体到命中的句子。
5. **定点改写**：只处理命中的句子，不要求整章重写。
6. **持续调整**：通过作者反馈、人物风格和读者偏好，逐步完善风格档案。

规则包和读者偏好默认关闭，需要作者主动启用。

## 排字房 UI

排字房采用约 420px 的 DSH 右侧栏布局，将作品、文风、规则和人物资料集中在写作工作区。

### 文风档案

- 支持多部小说导入、分章整理和字数统计。
- 从作品中提取 20 维文体指纹。
- 指纹只提供 `close`、`deviate`、`unknown` 三种判断，不生成作品分数或排名。
- 支持文风简报、定点检查和句子改写。

### 规则包

提供四组独立规则包，全部默认关闭：

| 规则包 | 规则数量 | 主要用途 |
|---|---:|---|
| `zh-slop-core` | 25 | 中文 AI 常见表达问题 |
| `zh-fiction` | 17 | 小说文本表达问题 |
| `zh-narrative` | 12 | 叙事表达问题 |
| `zh-punctuation` | 5 | 标点使用问题 |

规则包用于辅助定位可疑表达，不代表对作品质量的判断，也不意味着命中就必须修改。

### 人物卡

人物表达风格可以从整本书中分批提案：

- 支持整书分批提取人物表达特征。
- 每条提案都保留证据，可以逐条回查原文。
- 提取结果先进入 `candidate`，由作者逐条确认后才成为正式资料。
- 全对白不能确认，不能仅凭对白内容直接认定人物风格。
- `getPersonaBrief` 提供只读人物简报，供 beat 使用。

人物卡不是自动设定。作者拥有最终确认权。

### 读者偏好

读者可以从章节段落中点选原文引用，并用五颗星表达喜欢或不喜欢。

- 偏好默认关闭。
- 读者评价必须经过作者确认。
- 确认后的偏好才会进入文风简报和 beat 的参考信息。
- 读者反馈是创作参考，不是替作者决定写法。

### 文风组合

支持 A/B/C 三组 `characterStyles` 绑定，让不同人物或创作场景使用不同风格组合。

- 保留组合数据与服务接口。
- 支持字段级冲突识别。
- 冲突内容并列呈现，不静默覆盖。

A/B/C 目前尚无独立的组合 UI。

### 视觉与交互

- 底色跟随 DSH 宿主，也支持纸白、白纸和墨黑。
- 规则包、人物卡和读者偏好采用独立 sheet。
- 对话框支持键盘 `Escape` 关闭。
- 支持 `Tab` 键焦点移动。
- 关闭对话框后归还原焦点。

## 边界

排字房负责帮助作者学习、参考和调整文风，不接管创作。

| 事项 | 约束 |
|---|---|
| 正文创作 | 不写正文 |
| 模型训练 | 不训练模型 |
| 作品评价 | 不给作品打分、排名 |
| 默认行为 | 默认关闭，不主动介入 |
| 规则包 | 默认关闭，由作者选择启用 |
| 读者偏好 | 默认关闭，作者确认后才生效 |
| 人物风格 | 提案不等于正式设定，必须作者确认 |
| beat 联动 | 只提供 `personaText` 只读建议，不修改 gate 或事实 |
| fade 联动 | 不做适配，按作者决定保持独立 |

排字房不会替作者判断什么才是好文风，也不会因为检查命中就要求作者修改。

## 数据与隐私

- 导入作品用于建立本地文风资料。
- 文风档案、人物卡、读者偏好和组合数据服务于当前创作项目。
- 不以导入作品训练模型。
- 不自动修改原始作品。
- 人物提取结果需要作者确认。
- 读者偏好需要作者确认后才能进入写作参考。
- 定点改写以命中句子为范围，不以整篇替换作为默认操作。

## 已知限制

以下内容是当前版本尚未完成或尚未验收的部分，不应视为已经验证的能力。

### 长篇真实作品验证

使用《斗罗大陆》进行了完整链路测试：

- 原著规模：2,854,436 字、687 章。
- 跑过从作品导入到读者偏好的链路。
- 原著章节中出现 20 字重合会触发 block。

这里的 block 是原文重合保护，不是文风判断，也不能据此认定原著已经通过文风检查。

**作者新稿 block=0 的对照测试尚未完成。** 因此，当前不能宣称真实长篇作品的全量检查已经通过。

### 宿主与交互验收

以下工作后置：

- DSH 宿主真实浅色、深色主题截图。
- 键盘操作手工复测。
- 空态和失败态验收。

当前 UI 与自动化测试结果不等于真实宿主验收完成。

### 人物风格提取

人物 extract 的真实模型表现尚未验收，现有测试使用假 LLM。

因此，人物卡的证据、提案和确认机制已有测试覆盖，但不能宣称真实模型提取效果已经通过验收。

### 系列插件适配

- `fade`：不做适配，这是作者明确决定的范围。
- `beat`：主要适配集中在 beat 侧的 voice-guidance。
- A/B/C `characterStyles`：已有数据和服务能力，但没有独立组合 UI。
