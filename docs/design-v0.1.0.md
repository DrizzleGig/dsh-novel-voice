## 0. 一页结论

### 0.1 一句话

> **风格不是聊出来的，是装进去的。**
> **AI 味也不是"清掉"的，是被更具体的选择挤出去的。**

所以 v0.1.0 的两件事，顺序不能反：

1. **装**：一次性导入多部小说 → 学出可执行的写作选择 → 编译成写前简报 + 语感样本。这一步决定"像不像你"。
2. **守**：写完之后，把还在的默认习惯定位到句子，只改那一句。这一步决定"会不会打回原形"。

只做第 1 件：写完是像的，但写着写着会滑回默认语域——模型没有"守住"的机制。
只做第 2 件：就是市面上那批"人化工具"，清掉了套话，也清掉了你。

**为什么"装"能替代"长期对话"**：对话记忆积累的是"作者说过什么偏好"，语料给的是"作者实际怎么写"——后者是分布证据加原文样例，前者只是一句话。这也是记忆型、人格型产品在小说文风上不够用的原因（§2.2）。

### 0.2 本轮拍死的十一个决定

| # | 决定 | 一句话理由 |
|---|---|---|
| 1 | 入口名 **创作风格**，面板名 **风格工作室**，只此两个名字 | 作者拍板；旧名「文风 / 文风工作室 / 声线」全部退役 |
| 2 | **目标不是"像人"，是"像你"**：把默认语域挤出去，剩下的才是作者的 | 追求"人味"会写出新的机器腔；追求"你的选择"才有可验证的标准 |
| 3 | 检查器**只给线索，不给分数** | Pennovia 自己的对照实验证明：未校准的 0–100 分，中性稿反而更高 |
| 4 | 只有**可定位、误报低**的四类特征能"判罪" | 其余（句长方差、词汇多样性）只能当画像，不能当缺陷 |
| 5 | 重写是**定点改写**：不改未命中、不新增事实、不追求方差 | "为参差而拆句"和"让模型补具体"是两种更糟的 AI 味 |
| 6 | 一切阈值**以档案为基线**，不设全网通用标准 | 古龙的短句不是缺陷；拿通用阈值套所有作者必然误伤 |
| 7 | **统计只进画像与重排，不进简报** | 模型数不准频率；写"短句占 35%"会变成做作的模仿 |
| 8 | Style Compiler 是核心，`voice_polish` 是第二个核心 | 没有编译器，分析白做；没有定点改写，编译器落不了地 |
| 9 | 多作品**不取平均**，v0.1.0 只允许作者手动组合 2–3 个模式 | 自动聚类延到 0.2，先保证"四不像"不会发生 |
| 10 | 模型调用**只用 `ctx.llm`**，且只有 `voice_polish` 会花钱 | 检查可离线、可回归；改写才调模型 |
| 11 | 先做**最小机制切片**（约 8 个工作日）证明有效，再做面板 | 沿用 fade v0.6 的教训：先证明机制，再证明界面 |

### 0.3 v0.1.0 交付什么

四个闭环 + 一个面板：

```text
① 导入闭环   3 部中文小说 → 分章 → 统计 → 场景索引（全本地，0 模型）
② 档案闭环   统计 + 技法卡 + 证据回查 → L1–L4 档案 → 作者确认
③ 写作闭环   voice_brief 编译写前简报 → 模型写 → voice_check 定位 → voice_polish 定点改写 → 复检
④ 反馈闭环   赞/踩/改稿 diff → 原始反馈落盘 → 候选规则（只记录，不自动升级）
   面板      侧栏「创作风格」→「风格工作室」：书架 / 风格 / 学习 三个 tab
```

**v0.1.0 的验收不看"像不像某位作家"，只看三件可测的事**：

- 检查器在冻结夹具上**能定位**（AI 段召回 ≥70%，人工段误报 ≤1 处/千字）；
- 定点改写后**命中的 AI 习惯显著减少**（L1 命中 ↓≥60%），且**未命中区域一个字都不改**、**不新增事实**；
- 作者盲选 10 组 before/after，**≥7 组选"改后"**；达不到就说明机制没成立，不许发版。

### 0.4 三个必须先说清楚的诚实判断

1. **我们不做"人化"，也做不到"保证检测器判不出"**。改写能击穿检测器（Krishna et al. 2023：改写让 DetectGPT 从 70.3% 掉到 4.6%），但那是检测器的问题，不是文本变好了。把检测器当 KPI 等于优化一个坏指标。
2. **"AI 味"里有一半不是 AI 的错**。句长齐整、爱用破折号、段末想升华——很多人类作者也这样，而且可能是作者本人风格。所以本方案把"可判罪"压到四类硬特征，其余全部降级为"提示，请作者看"。
3. **学风格的天花板在"选择"，不在"词汇"**。模型能学会"这个作者在紧张场景不写心理、只写动作"，学不会"这个作者的比喻为什么好"。所以档案里禁止出现"简洁有力""细腻克制"这类形容词，只允许出现可执行、可检查的选择。

## 2. 问题重述：个性化风格 = 去 AI 味

### 2.1 作者这次的补充，把两个问题并成了一个

> "去 AI 味，换句话说，就是形成个性化风格……让这些风格的形成，不再是通过不断地、长期地对话，而是一开始就输入进去的很多小说文本，学习小说的写作风格和文笔，形成个性化风格。"

这句话把产品从"清理工具"改成了"初始化工具"，并且给出了明确的对照组：

| 做法 | 怎么形成风格 | 慢在哪 | 我们要换的 |
|---|---|---|---|
| ChatGPT 记忆 / 个性化设置 | 长期对话里一点点记 | 要聊很久；记的是"作者说过什么偏好" | 一次导入，直接学"作者实际怎么写" |
| 人格 / 角色模式（GPTs、Gems、角色卡、智能体） | 一次设定一个"谁在说" | 只给说话者性格，不给叙述句法 | 只借它"一次设定"的形态，不用它的内容 |
| 我们的做法 | 一次导入多部作品 → 档案 → 编译 | 导入要花一次时间 | 用分布证据 + 原文样例，替代长期对话积累 |

三句话记住区别：

- 记忆型：**知道你偏好什么**；
- 人格型：**知道谁在说**；
- 语料型：**知道你怎么写**。

小说文风要的是第三种。前两种不是没用，是补充：记忆用来记"作者这半年变了"，人格用来做 v0.3 的「人物声线」。

### 2.2 三条把风格装进模型的路径

| 路径 | 代表 | 风格存在哪 | 冷启动成本 | 对"小说文风"够不够 |
|---|---|---|---|---|
| **A 对话记忆** | ChatGPT Memory / 个性化设置 / Claude Projects 记忆 | 记忆条目 + 自定义指令 | 长期对话 | 不够：记的是偏好陈述，不是写法 |
| **B 人格设定** | GPTs、Gemini Gems、Character.AI、SillyTavern 角色卡、豆包/星野智能体 | system prompt 里的角色卡 | 一次设定 | 只解决"谁在说"；角色卡写不出句法、节奏、留白 |
| **C 语料引导** | Claude Styles、Jasper Brand Voice、Sudowrite Style、Novelcrafter 写作样本、Pennovia | 一句风格描述 / 参考片段 / 自建档案 | 一次导入 | 方向对，但市面普遍停在"整篇蒙一层膜" |

我们站在 C，但要比现有的 C 多三件事：

1. **档案化**：不是一句描述，是带证据、带区间、可版本、可回滚的档案；
2. **编译**：不是每次整份塞进去，是按当前场景取 3–5 条 + 样本；
3. **定位**：不是写完打一个分，是把残留的默认习惯指到句子。

这三件事就是 v1 与本方案的落点；§4 会逐个核对市面上谁做到了哪一件。

### 2.3 "风格"拆成五件可执行的事

形容词不可执行。"克制"不可执行，"对峙场景不直接命名情绪，用动作和停顿"可执行。所以档案里只允许五类内容：

| # | 类型 | 例子 | 怎么检查 |
|---|---|---|---|
| 1 | **选择**（写什么、不写什么） | 紧张场景只写动作与生理，不写"他感到紧张" | 词表 + 句法位置 |
| 2 | **比例**（各成分占多少） | 对话 30–40%，心理 ≤20%，描写 30–40% | 统计成区间；**只做画像，不进简报** |
| 3 | **禁区**（绝不出现的短语/句式） | 眼中闪过一丝、空气仿佛凝固、不是……而是…… | 正则 + 密度 |
| 4 | **语域**（写给谁、什么距离） | 第三人称限知、叙述者不评价、不解释因果 | 人称/评价句/连接词 |
| 5 | **锚点**（语感样本） | 参考作品 ≤80 字短引文；作者旧作 ≤400 字样段 | 逐字回查 / 直接作 few-shot（§5.4.1） |

**明确不进档案的**：`简洁`、`有力`、`细腻`、`冷峻`、`有画面感`、`节奏感强`、`文笔老练`。这些词进了档案，模型只会把它们翻译成它自己的平均值——也就是 AI 味本身。

### 2.4 "AI 味"拆成五层，只有第一层能判罪

| 层 | 表现 | 能不能自动判 | 处理方式 |
|---|---|---|---|
| **L1 表层习惯** | 套话短语、"不是 A 而是 B"、段末升华、抽象情绪直述、与原文过长重合 | **能**（正则 + 位置 + 密度，误报低） | 定位 → 定点改写 |
| **L2 分布特征** | 句长偏齐、段长偏匀、对话占比异常、标点单一 | **只能报，不能判** | 与档案区间比，给"偏离提示" |
| **L3 具体性** | 通篇"一种说不出的感觉"、没有可触摸的名词 | 半能（词性比例可测，是否"够具体"不可测） | 报比例；改由作者提供细节 |
| **L4 过度解释** | 每件事都交代因果、怕读者不懂 | 半能（连接词密度可测，"该不该解释"不可测） | 报密度；规则由作者定 |
| **L5 语域** | 助手腔、总结腔、面面俱到 | **不能**（这是判断，不是检测） | 只在简报里用规则约束；不做事后检测 |

**这张表是全案的地基。** 市面上"去 AI 味"工具的全部错误，都来自把 L2–L5 当成 L1 来处理：给整篇打一个分、按词表无差别删词、为了"参差"硬拆句。

但要记住它在这一版里的**地位**：L1 检测器是守门员，不是主力。真正把 AI 味挤出去的是 §5.4 的编译与语感样本；守门员只负责把溜回来的那几个习惯指出来。

### 2.5 由此得到的产品主张

> **先把你的写法装进去，再把溜回来的默认习惯挡回去。**

三个直接推论：

1. **编译质量 > 检测器数量**：简报里没有具体的、可执行的选择，检测器再准也只是在收拾残局；
2. 检查器的输出必须是**位置 + 原句 + 理由**，不是分数；
3. 改写必须是**最小编辑**，且能证明"没动的地方真没动"。

## 3. 交付物与边界

### 3.1 v0.1.0 的四个闭环，缺一不算完成

| 闭环 | 入口 | 成功的样子 | 对应章节 |
|---|---|---|---|
| ① 导入 | `voice_import` / 面板「书架」 | 3 部 10 万字导进来，章节识别可修正，容量有数 | v1 §5 / 本方案 §5.2 |
| ② 档案 | `voice_learn` + `voice_profile` | ≥10 张技法卡 100% 引文可回查；L1–L4 档案可确认 | v1 §4、§6 / §5.3 |
| ③ 写作 | `voice_brief` → `voice_check` → `voice_polish` | 简报正文 ≤600 字（有旧作时附 ≤400 字样段）；检查能定位；改写只动命中处 | v1 §8 / §5.4–5.6 |
| ④ 反馈 | `voice_feedback` | 反馈落盘；候选规则出现但**不自动升级** | v1 §9 / §5.7 |

### 3.2 明确不做（v0.1.0）

| 不做 | 理由 | 什么时候做 |
|---|---|---|
| 自动聚类多作品为 Mode | 聚类不可解释，先让人选 | v0.2 |
| 候选规则自动升级为 confirmed | 红线：不能无确认升级 | v0.2（半自动，仍需确认） |
| A/B 盲测统计报告 | 先做单次预览，20 对盲测是发版前人工流程 | v0.1.0 的验收流程，不做进产品 |
| 角色声线 / 盲测 / 口癖 | 降级为 v0.3 子模块「人物声线」 | v0.3 |
| EPUB / PDF / DOCX | v1 只做 TXT / MD，假支持比不支持更糟 | v0.2 起逐个评估 |
| 训练 / LoRA / 微调 / embedding | 插件里做不了，也不该做 | 不做 |
| 文笔评分 / 作家相似度 / 排行榜 | 伪精确 + 版权伦理 | 永久不做 |
| 检测器分数作为产品指标 | 检测器有偏且可击穿 | 永久不做 |
| 全量 Profile 注入 | 上下文爆炸 + 规则打架 | 永久不做 |

### 3.3 独立性与依赖

- **只装 voice 就能用**：不 import beat / fade / fanfic；不读它们的数据也能跑完整闭环。
- **有兄弟就增强**：存在 fanfic 契约时，`voice_check` 追加「视角 / 称呼 / 知情 / 禁忌」四项（复用 `GATE_DETECTORS` 的判定思路，不 import 它的运行时）；存在 beat 账本时，`voice_brief` 的 `hardConstraints` 可读 `book.json`（只读）。
- **能被读**：暴露只读服务 `novelVoice`，供 conductor / Pro 读简报、规则、状态；不写别人的数据。
- **模型**：只用 `ctx.llm`，不引入 SDK / API key。模型解析顺序：插件配置 `{provider, model}` → `ctx.agentDefaultModel.currentSelection()` → `model-unavailable`（降级为纯本地检查，不伪造）。

## 4. 尽调：这项能力，公开与非公开平台做到了哪一步

> 结论先行：**产品市场上没有；开源侧有一个同构原型（skill 组），但缺 UI、缺场景子档案、缺句子级定位。**
> 市面上真正跑通的是三段：**样本 →（统计/模型）→ 一段风格描述 → 塞进上下文**。缺的恰恰是最难的第四段：**改哪里、改到什么程度、谁来签收**。
> 因此 v0.1.0 的策略是"抄四个局部机制 + 自建第四段"，而不是"接一个开源引擎"。逐一对照见 §4.8。

### 4.1 调研口径

证据只认三种：**能读到的源码/字段名**、**作者自己承认的限制**、**同行评审论文**。商业产品的机制只能从官方文档与可观察行为推断，一律标「推断」。行业经验帖（"去 AI 味"清单）标「工程实践」，不作为机制成立的证据。**非公开/企业内部工具没有可核证据**，本节不猜。

### 4.2 八个开源项目，机制逐条拆

| 项目 | 中间表示 | 生成时怎么用 | 评估 | 我们能抄的 | 不能抄的 |
|---|---|---|---|---|---|
| **Pennovia**（author-voice engine） | `VoiceProfile` JSON：`avg_sentence_words`、`sentence_std_dev`、`short_sentence_rate`、`em_dash_rate`、`top_transitions`、`signature_phrases`、`sample_sentences` 等标量 | `_build_prompt()` 把**数字翻成自然语言**再给比例指令（"n% 短句、m% 长句，按同比例混句"），温度 0.8；语料原串降级为 `UNTRUSTED STYLE EVIDENCE` | 加权 rubric：`voice_match` 40 + `transition_match` 20 + `style_match` 20 + `no_ai_cliches` 20，70 分及格 | 数字→描述、比例指令、**注入隔离**（把参考原文标成不可信数据，防提示注入）、`no_ai_cliches` 这一项 | 0–100 分。作者自己在 `docs/VALIDATION.md` 承认：**中性对照稿的分数比带声线引导的稿更高**，且"分数未经校准" |
| **voice-profile-mcp** | `profile.json`：`registers[r].bands[k] = [lo, hi]`、`center`、`n_docs`、`provisional`、`banned[]` | 不生成。`check_draft` 逐特征 pass/fail，并给"往哪边挪" | 10/90 百分位 + `MIN_HALF` 最小半宽（如 `mean_sent_len: 2.5`）防单篇定标；样本 <5 或 <3000 词标 `provisional` | **working range（区间）而不是目标值**；最小带宽；`provisional` 状态 | 只有 10 个表层量、英文向、无 held-out |
| **styleprofile** | `calibration.by_length`（分长度 rms、Delta 中位与 95%/99% 上界）、`calibration.drift`、`calibration.bootstrap` | 不生成，纯评分器 | Delta = 加权平均 \|z\|；`LLM-likeness` = 用"同一 brief 的模型草稿"当**对比集**算效应量；AUC + bootstrap | **held-out 校准**、**对比集学权重**、按长度取阈值 | 段落级漂移实验性：作者自述某语料 **33% 假阳**；"flagged chunk 是去读的指针，不是证据" |
| **MYNAH** | Markdown 档案：`Tone`、`Formality`、`Sentence length`、`Signature moves`、`Avoid`、**`Imperfections`**（默认关闭） | COMPOSE 阶段把该 context 的 markdown 整块塞进上下文 | 无自动评估 | **按场景分桶**；"3 次以上复现才算风格，一次算噪音"；**保留不完美**这一栏 | 纯 markdown、无量化、只支持单一模型平台 |
| **novel-craft** | 31 份 craft spec，其中 `04-anti-ai.md` 是 **AI-1…AI-11 负面规则 + 可 grep 禁词速查表**（然后/接着/于是/说不清/莫名/她感到/一股 XX 涌上心头…） | 按"何时读"路由规格进上下文；完稿派 `paragraph-reviewer` 过 17 维 | 无量化，清单式审查 | **负面规则 + 可直接 grep 的禁词表**，零依赖，能直接搬进 Node | "34 位作家技法库"本质是文档集合；未披露失败模式 |
| **blader/humanizer**（~70k★） | 26 条编号 pattern，分 A–F 六组（staging / rhythm / inflation / formatting / leftovers / wrong-reader） | 四步：标 tell → 草稿 → 查漏（先查事实丢失）→ 定稿。**样本优先于全局规则**："样本里用破折号，就保持同样比例" | 无自动评估 | **tell 强度分级**（§1–5 一见即改，其余"单独出现不算"）；**先用样本量基线再决定禁不禁**；多条共现才判定 | 英文语料；无定位、无保真校验 |
| **stylo**（R） | 高频词相对频率 → z-score 矩阵 | 不生成 | Delta / Cosine Delta / Rolling Delta / General Imposters | **Delta = z-score 后取平均绝对偏差，20 行 JS 能复刻**；Rolling Delta 的滑窗定位 | R 运行时；小样本不可靠 |
| **TinyStyler** | 800M 模型 + authorship embedding（可插值控制强度） | 条件生成挂在 embedding 上 | 作者归属自动指标 + 人工，论文称优于 GPT-4 | 只借"风格强度可插值"的产品直觉 | 整条模型路线在 Node 插件里是死路 |

**三条从代码里读出来的硬结论：**

1. **没有校准的风格分是有害的。** Pennovia 的对照实验是现成的反证：同一篇稿子，中性版得分高于带风格引导的版。所以本方案**不输出任何 0–100 分**，只输出"命中位置 + 偏离区间的方向"。
2. **区间比目标值有用。** voice-profile-mcp 用 `[lo, hi]` + 最小半宽 + `provisional`，比"平均句长 8.2"更抗噪，也比单点阈值更不容易误伤。本方案 L2 全用区间。
3. **市面上的"去 AI 味"停在整篇。** 它们给整篇一个分，然后整段重写；**检测和改写之间没有定位这条链**。所以它们的成功只能体现在"检测器分数掉了"，不能体现在"这一句被修好了"。这正是我们的空位。

**如果只挑三个来学**：`styleprofile`（怎么用 held-out 校准，不校准的分数会骗人）、`voice-profile-mcp`（怎么用区间 + 最小带宽，而不是目标值）、`humanizer`（怎么让示例压过全局规则）；再加 `novel-craft` 的禁词 grep 表当零成本起点。**Pennovia 的价值是反面教材**：它证明了没有校准的风格分会让稿子更差，这一点比它的任何功能都值钱。

### 4.3 商业产品：链路对，粒度粗

| 产品 | 官方描述的机制 | 实际粒度 | 判断 |
|---|---|---|---|
| **Claude Styles** | 用作者自己的写作样本创建自定义风格，生成时套用 | 整篇、全局 | 链路成立；无场景区分、无写后校验 |
| **Sudowrite Style** | 作者手写一段风格描述影响语气、用词、句法 | 整篇、描述级 | 最弱的一档：形容词 → 模型平均值 |
| **Novelcrafter Writing Samples** | 写作样本放进 snippet，用 prompt preset 引用 | 整篇、上下文级 | 等于 few-shot，无档案、无证据 |
| **Undetectable.ai / StealthGPT / HIX Bypass** | 检测 → 改写 → 再检测；StealthGPT 自述"句级重写"，HIX 自述多档 aggressive | 句/段，但**盲改** | 机制是"对抗检测器"，不是"改好文字"；所有绕过率都是厂商自报 |

**共同的空洞**：四类产品都假设"风格是一层可以整体蒙上去的膜"。而写作的实际情况是：**风格是几千个微观选择，AI 味是几十个可定位的习惯**。膜蒙不上去，只能一处一处改。

### 4.4 学术结论：五条能改变设计的事实

| # | 结论 | 证据强度 | 对本方案的影响 |
|---|---|---|---|
| 1 | **AI 味的根因是后训练把输出分布收窄到"平均好文"**，不是某几个词 | 强（Kirk et al. 2024；Doshi & Hauser 2024） | 不能靠"加词/换词"解决；只能靠**换选择**与**换语域**。禁语表是补丁，不是主药 |
| 2 | **统计特征不能写进 prompt**：模型数不准频率，写"多用虚词/占 35%"会变成做作的模仿；且小样本 Delta 不可靠（<3000 词"灾难"，5000–10000 才稳定） | 强（Eder 2015/2016；Stamatatos 2009） | **统计只进画像、重排与评估，不进简报**。简报只写可感知、作者说得清的事 |
| 3 | **句/场景级风格迁移可行，整书作者模仿不可靠** | 强（Reif et al. 2022，句级改写；后续作者模仿研究在新闻/邮件可近似，博客/论坛等隐式风格失败） | 我们只做 **span 级**改写；不做"整章重写""模仿某作家" |
| 4 | **示例 > 形容词**；且示例要"覆盖"全局规则（样本用破折号就保留） | 中（few-shot 实践与 Reif 2022 的"示例 + 指令"组合；humanizer 的"样本覆盖规则"属工程经验） | 锚点必须进简报，且**锚点优先于通用禁则** |
| 5 | **AI 检测器不可作指标**：非母语者过半被误判；改写可把 DetectGPT 从 70.3% 打到 4.6% | 强（Liang et al. 2023；Krishna et al. 2023；Sadasivan et al. 2023） | 产品里**不出现检测器分数**；验收用作者盲选 + 本地指标 |

另外两条只影响边界，不影响主设计：

- **温度只影响随机性，不影响语域**（Peeperkorn et al. 2024）：`ctx.llm` 只有 `temperature`，我们可以用它增加候选多样性，但不能指望它去 AI 味。
- **LLM-as-judge 有自我偏好**（Panickssery et al. 2024）：所以"像不像人"不能交给模型打分，只能交给作者盲选。

### 4.5 被反复证明有效的五个机制（我们的取材清单）

| # | 机制 | 出处 | 我们怎么用 |
|---|---|---|---|
| M1 | **held-out 校准 + 区间** | styleprofile / voice-profile-mcp | 统计留 10–20% 章节不建档案；所有 L2 指标用 `[lo, hi]`，样本不足标 `provisional` |
| M2 | **对比集**（负样本） | styleprofile 的 LLM-likeness | 存「AI 初稿 → 作者改稿」成对样本；学习与重排都拿它当负样本 |
| M3 | **可 grep 的负向清单** | novel-craft / Pennovia / humanizer | 内置一份中文 AI 套话表 + 每本书的追加表，全部可定位、可回归 |
| M4 | **样本覆盖全局规则** | humanizer | 锚点里出现破折号/省略号，就不再套用"禁用破折号"的通用禁则 |
| M5 | **定位到句 + 最小编辑** | 市面普遍缺；本方案补 | `voice_polish` 只改命中片段，改完证明未命中区域零改动 |

### 4.6 被证伪或明确有害的六种做法（写进红线）

| 做法 | 为什么有害 | 证据 |
|---|---|---|
| 全局同义替换 | AI 本来就不敢重复，再换更假；毁术语与人物口癖 | 工程实践共识；换词不改变分布形状 |
| 为"参差"硬拆句 | 句长方差的人机差异在配对复测里几乎消失；机械参差化比不改更糟 | 工程实践（lieflat 项目自述规则被自己降级） |
| 按词表无差别删词 | 删掉的多是作者口头禅；对中文"AI 味"的词表效应量很小 | 工程实践（"赋能/闭环"类词 δ≈+0.10） |
| 让模型"补具体" | 它会编数字和细节，"这比 AI 味更糟" | 工程实践（stop-slop-zh 原文） |
| 拿检测器分当 KPI | 检测器有偏且可被改写击穿；优化它等于优化坏指标 | Liang 2023；Krishna 2023 |
| 过度口语化 | 给第三人称/古装/严肃题材硬塞"说实话/说白了"，直接毁语域；三个月后这些词就是新套话 | 工程实践 |

### 4.7 可行性结论：一张能做/不能做的表

| 机制 | 依赖 | 判断 |
|---|---|---|
| 本地确定性统计 + 区间画像 | 纯 JS | **能做**，v0.1.0 必做 |
| 模型辅助技法提取（带引文回查） | `ctx.llm` + 本地校验 | **能做**，v0.1.0 必做；引文找不到就丢弃 |
| 写前编译（规则 + 锚点 + 禁区） | 纯 JS | **能做**，v0.1.0 核心 |
| 可定位的四类 AI 习惯检测 | 正则 + 位置 + 密度 | **能做**，v0.1.0 核心 |
| 定点改写 + 保真校验 + 复检 | `ctx.llm`（temperature 可调）+ 本地 diff | **能做**，v0.1.0 核心；每处 ≤1,200 字，最多 2 轮 |
| 候选重排（2–3 份，本地打分） | 纯 JS | **能做**，但只能给"指针"，不能给"好坏" |
| 反馈落盘 + 候选规则 | 纯 JS | **能做**；**不自动升级** |
| Delta / 字符 n-gram 距离 | 纯 JS（20 行） | **有条件**：只用于**离线评估脚本**与整书级比较；单章 <3000 字不可信，必须标样本量 |
| 风格向量 / CAA / 激活干预 | 白盒激活 | **不能**（API 模型无激活） |
| LoRA / DPO / 微调 | GPU + 训练数据 | **不能**（也不该由插件承担） |
| logit_bias / grammar 约束解码 | 适配器支持 | **不能**（本机 `ctx.llm` 的采样只有 `temperature`/`maxTokens`/`stop`） |
| 检测器分数 / "像人"评分 | 不可靠 | **不做**（红线） |
| 整章"重写得更像人" | 不可控 + 编造 | **不做**（只做定点） |

### 4.8 语料引导文风：市场现状（2026-11）

**先直接回答作者的问题：有可以参考的，但没有能直接用的。**

#### 4.8.1 三类产品，成熟度完全不同

| 类 | 代表 | 成熟度 | 它能给你什么 | 它给不了什么 |
|---|---|---|---|---|
| **A 对话记忆** | ChatGPT Memory、Claude Instructions / Projects | 成熟 | "作者说过什么偏好" | 作者实际的句法与节奏 |
| **B 人格设定** | GPTs、Gemini Gems、Character.AI、SillyTavern 角色卡、豆包/星野智能体 | 成熟 | "谁在说"：口癖、立场、反应模式 | 叙述层文风：叙述距离、句法、留白 |
| **C 语料引导** | Jasper Brand Voice、Sudowrite Style、Novelcrafter、NovelAI Modules、`novel-style-skills` | **早期/空白** | 一段风格描述或一份档案文本 | 场景化编译、句子级校验、可回滚的学习 |

B 类值得单独说一句：把"人格蒸馏"改造成"文风蒸馏"这条路已经有人走过（`novel-style-skills` 的作者明确说自己是受人格蒸馏项目 `forge-skill` 启发，把逻辑从人格改成小说作者文风）。这恰好证明了 **persona ≠ prose style**：前者能迁移的只有"人物声音"，不是叙述者的句法。

#### 4.8.2 C 类逐项现状（都核过官方文档）

| 产品 | 输入 | 中间表示 | 跨项目复用 | 写后校验 | 证据与限制 |
|---|---|---|---|---|---|
| **Jasper Brand Voice** | 上传写作样本 | 账号级 voice 文本 | 能 | 无 | 官方帮助写明"upload examples…analyze your tone, style, and key characteristics"；正文被 Cloudflare 拦，只取到索引摘要；营销文案取向，无叙事文风维度 |
| **Claude Styles** | 曾：用样本创建风格 | **现行文档已无 Styles 条目**，风格能力并入 Skills（"apply communication patterns based on your own writing or preferences"） | 能 | 无 | 官方个人化文档（2026-10 更新）只列 Instructions / Project instructions / Skills；从"样本蒸馏"退回"人写 SKILL.md" |
| **Sudowrite Style** | 手填一句话 | Story Bible 里的文本框 | 否（Series 只共享角色/世界观/大纲） | 无 | 官方示例就是 "Lush prose"、"Spare and haunting. Written in short sentences…" |
| **Novelcrafter** | 人写 Prompt Persona | 全局注入文本 | 能 | 无 | 官方自称"类似聊天工具的 memory"；没有写作样本分析 |
| **NovelAI Modules** | 曾可训练自定义模块 | 微调权重 | 否 | 无 | 官方：Module 是 legacy，**已停止支持训练新自定义模块** → 权重路线对大众关闭 |
| **Type.ai** | 手写规则 | 规则文本 | — | 无 | 官网 "Write in your style: Create custom writing rules" |
| **中文产品**（蛙蛙/墨狐/笔灵/秘塔/彩云/阅文妙笔/番茄） | 选风格标签或预设 | 预设 prompt | 否 | 无 | 均未找到"从语料学文风"；阅文妙笔做的是千万字级理解与伏笔回顾，属于**长篇记忆**，不是文风 |
| **`novel-style-skills`**（开源，MIT，9★） | 多部小说样本 | `novel_styles/{name}/style.json` + `style.md` + `versions/` | 能 | **有 `eval-novel-style`** | 唯一同构：`forge` → `use` → `eval` 两段式；无 UI、单档案、无场景子档案 |

#### 4.8.3 两个值得注意的信号

1. **连 Anthropic 都把 Styles 并回了 Skills**。说明"样本蒸馏风格"的产品化难点不在提取，而在"每一次生成都稳定用上、且不跑偏"。这正好支持我们"编译 + 守住"的两段设计。
2. **NovelAI 关掉自定义模块**。参数级（微调）路线对大众产品关闭了，剩下能走的就是上下文级——也就是本方案这条路。这不是我们选得保守，是市场已经替我们试过另一条。

#### 4.8.4 我们与 `novel-style-skills` 的差异：该抄的抄，该补的补

它的 `forge → use → eval` 与本方案 §5 的"记 → 写 → 查"是同一个判断，独立收敛到同一处，说明方向没错。差别在深度与形态：

| 维度 | 它 | 我们 | 判断 |
|---|---|---|---|
| 形态 | Codex / Claude Code 的 skill 组 | DSH 插件：侧栏 + 7 个工具 + 本地数据 | 它无 UI，我们有 |
| 档案 | 单份 `style.json` | L1–L4 + 场景子档案 + 区间 + 反例 | 补场景 |
| 编译 | 加载精简 runtime card | 按章节/场景编译 + 硬约束 + 预算 + 样段 | 补编译 |
| 校验 | `eval` 给漂移与 AI 腔评估 | 定位到句 + 五道校验 + 最小编辑 | 补定位 |
| 学习 | `versions/` 目录 | 快照 + 回滚 + append-only 反馈 + 候选规则 | 补闭环 |
| 融合 | 按层融合多作者（叙述/句法/词汇/对白/情绪/反 AI） | 模式 + 场景权重 + 冲突表（v0.2 才自动聚类） | 第一版它更完整，我们后补 |
| 语料 | 用户提供样本 | 分层：参考 ≤80 字 / 作者旧作 ≤400 字样段 | 补版权与 few-shot |

**要抄的三件事**：两段式（先 forge 档案，再 use 档案）、按层融合而不是整本平均、写完必须 eval。
**不抄的三件事**：单档案（不做场景子档案）、评分式 eval（我们改成定位）、skill 形态（我们是插件）。

#### 4.8.5 结论：空位在哪

产品市场里，**没有人在做**"一次导入 3 部小说 → 结构化档案 → 按章节编译 → 写后定位到句"。开源侧有一个同构原型，但它是单人项目（9★、无 UI、单档案、评分式评估）。

所以我们的位置不是"再做一个文风分析器"，而是把这条链**产品化**，并且只做四件它没做的事：

1. **场景子档案**：战斗与日常用不同参数，不取平均；
2. **句子级定位**：不说"这篇偏离了"，说"这一句是默认语感"；
3. **版本 + 反例**：每次学习可回滚，反例带位置；
4. **插件形态**：不用配 Python、不用开终端，侧栏里点三下。

## 5. 机制：读 → 记 → 写 → 改 → 学

### 5.0 为什么这套机制可能有效（可证伪的因果链）

不要从"AI 应该写得更像人"出发——那是个不可验证的目标。从这条链出发：

```text
模型默认只有一个语域（后训练把分布收窄，有证据）
  → 这个语域在文本上表现为「可数的习惯」+「平均化的选择」（可测）
    → 平均化的选择可以被更具体的选择替换（编译 + 示例，可控）
      → 替换不掉的习惯有位置（可定位）
        → 有位置就能最小编辑（可控）
          → 编辑完能验证「该改的改了、不该动的没动」（可证伪）
            → 作者签收（有权）
              → 签收结果变成下一本书的禁语与规则（可积累）
```

每一步都有对应的验收指标（§11）。**任何一步不成立，整个机制就不成立**，我们据此停手，而不是发一版"感觉变好了"的东西。

### 5.1 五段总览

```text
参考作品 / 作者旧作
  │
  ├─ ① 读 measure   分章 → 分场景 → 确定性统计 → 分层取样         （0 模型）
  │
  ├─ ② 记 extract   技法卡（模型提 / 引文校验 / 作者确认）→ L1–L4 档案
  │
  ├─ ③ 写 compile   当前章节 + 场景 + 人物 → 简报 ≤600 字 + 样段 ≤400 字   （0 模型）
  │
  ├─ ④ 改 repair    lint 定位 → 只改命中窗 → 五道校验 → 复检 → 签收 （1–2 次模型/窗口）
  │
  └─ ⑤ 学 record    赞/踩/改稿/意见 → 原始事件落盘 → 候选规则       （不自动升级）
```

代码里这条链叫 `voice-loop`；界面上不出现这个名字，界面上只有「生成简报 / 检查本章 / 定点改写」三个动作。

### 5.2 ① 读：先分场景，再统计；统计只作画像

**分场景**（沿用 v1 §6.2，六桶）：对话 / 动作战斗 / 心理情感 / 描写环境 / 日常过渡 / 悬疑对峙。启发式优先，边界场景才问模型，且作者可改。

**统计六组**（沿用 v1 §6.3）：句法、段落、对话、叙述、修辞、节奏。每项带 `sampleSize` 与 `confidence`。

**本方案新增的三条硬约束：**

| 约束 | 内容 | 理由 |
|---|---|---|
| C1 | 统计结果**不得**以数字或百分比进入简报 | 模型数不准频率；写"30–40% 短句"会变成做作模仿（§4.4-2） |
| C2 | 统计结果**只**用于三处：区间画像、偏离提示、候选重排 | 统计是尺子，不是笔 |
| C3 | 每项统计必须连带 `n`（样本量）；`n < 30` 标 `insufficient`，不参与偏离判断 | 小样本的"特征"多半是噪声 |

**样本量门槛**（直接决定面板上显示什么）：

| 作品字符数 | 档案状态 | 面板表现 |
|---|---|---|
| < 8,000 | `insufficient` | 只显示"样本不足，仅供试读"，不生成 L2 区间 |
| 8,000–30,000 | `provisional` | 区间加宽 1.5 倍，标"低置信" |
| ≥ 30,000 | `usable` | 正常 |
| 单章 < 3,000 字 | 不做 Delta / 字符 n-gram 结论 | 学术上 <3000 词即"灾难"（Eder 2015），中文只会更差 |

### 5.3 ② 记：技法卡必须是"选择"，并且带一个可执行谓词

卡片结构（在 v1 §4.2 基础上加两个字段：`check` 与 `ttl`）：

```json
{
  "id": "r-012",
  "layer": "L3",
  "title": "紧张场景不命名情绪",
  "rule": "人物面对压力时，先写动作、停顿和细微反应，而不是直接说明他正在紧张。",
  "instruction": "紧张场景中，用可观察的动作与生理细节承接情绪；允许必要的心理信息，但不给情绪命名。",
  "scope": { "sceneTypes": ["对峙", "试探", "压力"], "pov": ["third-limited"] },
  "check": { "detector": "emotion-naming", "params": { "maxHits": 0 }, "severity": "warn" },
  "status": "confirmed",
  "confidence": 0.82,
  "supporting_evidence": [{ "workId": "w-001", "chapter": 12, "offset": 4821, "quote": "他指尖停在门把上，迟迟没有转动。" }],
  "contradicting_evidence": [{ "workId": "w-002", "chapter": 30, "offset": 1203, "quote": "他忽然意识到，自己其实一直在害怕。", "note": "该作高压场景也会直接命名情绪" }],
  "observations": 12,
  "ttl": null,
  "version": 3
}
```

**新增 `check` 的理由**：没有可执行谓词的规则只是文学评论。一条 L3 规则必须能落到一个检测器上；落不到的，只能当 L1 总则（进简报的"总则"一行），不占规则位。

| 层 | 是否必须有 `check` | 例子 |
|---|---|---|
| L1 风格画像 | 否（1–2 句总则） | "克制、动作外化、不总结" |
| L2 表达特征 | 是（指向统计区间） | `{ detector: "rhythm", metric: "sentenceCv", band: [0.45, 0.75] }` |
| L3 写作策略 | **是**（指向具体 detector） | 上面的 `emotion-naming` |
| L4 场景适配 | 是（指向模式权重） | `{ scene: "战斗", weights: { tight: 0.75 } }` |

**证据硬门槛**（沿用 v1，更严）：

- 每条 `quote` 必须能在原文逐字找到（忽略空白差异）；找不到 → 丢弃整卡，记 `evidence-not-found`；
- 引文 ≤80 字，不存整段；
- 反例也必须带 `workId/chapter/offset`，"有时不是"这种话不收；
- 模型输出 JSON 解析失败重试 1 次；仍失败 → `model-output-invalid`，保留统计，不阻塞。

**升级条件**（硬规则，v0.1.0 只做人工确认）：≥2 个独立观察、跨 ≥2 章节/场景、有可核证据、有反例、作者点"确认"。

### 5.4 ③ 写：编译器（Style Compiler）

输入 → 输出：

```text
输入：profileId + 章节号 + 场景类型 + 视角 + 在场人物 + 本章任务 + 正文预算(600) + 样段预算(400)
输出：markdown 简报（正文 ≤600 字；有作者旧作时附 ≤400 字样段）+ 引用清单（ruleIds / anchors / sources / version）
```

编译七步（在 v1 §8.3 基础上收紧）：

1. **解析场景**：显式参数 > fanfic 契约（若存在）> 档案默认权重；
2. **选模式**：场景权重归一化，得到 1–2 个模式（v0.1.0 只有沉浸 / 紧凑 / 克制三个固定模式，作者手动调权重）；
3. **筛规则**：只取 `confirmed`；按 `scope` 过滤；按 `confidence × recency × 相关性 × 作者权重` 排序，最多 5 条；
4. **写成人话（关键）**：把 L2 区间翻成**可感知描述**，不带数字——
   - ~~"句长中位 16，短句 30–40%"~~ → "以中短句为主，偶尔用一个长句压住节奏；不要连续三个长句"；
   - ~~"心理描写 20%"~~ → "心理点到为止，能让动作接住的就别写心里话"；
   - ~~"比喻密度低"~~ → "少用长比喻；要用就用短、具体、能摸到的东西"；
5. **加硬约束**：视角、称呼、禁忌、题材红线（来源标 `fanfic-contract` 或 `book.json`）；
6. **冲突处理**：同优先级冲突不合并；取场景更具体的一条，另一条标 `conflict`；`strict` 模式直接 `blocked`；
7. **加锚点 + 裁剪**：参考锚点 1 条（≤80 字，匹配当前场景）；有作者旧作时再取 1 段样段（≤400 字，同场景优先）。预算顺序：先删参考锚点 → 再删第 4、5 条规则 → **样段最后删** → **永不删硬约束**。

#### 5.4.1 两类锚点：为什么"你自己的段落"比"别人的金句"有用

这是"语料初始化"能不能成立的关键。给示例比给形容词有效——few-shot 风格迁移的常规做法就是"示例 + 风格指令"一起给（Reif et al. 2022 的增强零样本本质上也是用示例教任务格式）。但 80 字的短引文只能示范"一个句子"，示范不了"一段话的节奏、停顿、段落怎么收"。

| 类型 | 来源 | 长度 | 用途 | 约束 |
|---|---|---|---|---|
| **参考锚点** `reference` | 导入的参考作品 | ≤80 字 | 语感样本：一个句子长什么样 | 必须逐字回查；≤80 字是为版权与"不诱导抄袭"；不进样段 |
| **作者样段** `own` | 作者自己的旧作（`sourceType: own`） | 200–400 字 | few-shot 示范：一整段的呼吸、断句、留白 | 只来自作者自己的文本；按场景检索匹配；**只学语气，不搬情节与人物** |

三条实现规矩：

1. **只从 `own` 语料取样段**。别人的作品整段放进上下文，既有版权问题，也会让模型直接搬句子、搬人物。
2. **按场景检索**：写对峙就取作者写过的对峙段，写日常就取日常段；没有同场景就取"最接近"的，并在简报里标注"场景不完全匹配"。
3. **样段里不许出现本章在场人物的名字**：避免模型把样段的剧情带进来。编译时对人名做遮蔽或换名（`林砚` → `他`），成本低，收益大。

> 一句话：**参考锚点是"看一句"，作者样段是"照着写一段"。** 没有第二样，所谓"一次导入就学会"就只能停在形容词。

**三种语料组合，三种结果**（这一点必须对作者说清楚，否则会期待错）：

| 书架里有什么 | 能学到什么 | 学不到什么 | 面板提示 |
|---|---|---|---|
| 只有参考作品（别人的） | 技法、禁区、句法倾向；像"你喜欢的写法" | 你的呼吸、你的留白；**不会像你** | "想更像你自己？导入 3–5 万字你自己的旧稿" |
| 只有作者旧作 | 句式、节奏、段落组织；像"过去的你" | 新技法；容易把旧毛病一起学回来 | "再放 1–2 部你认可的作品，补技法" |
| 两者都有（推荐） | 骨架来自你自己，技法来自参考 | —— | 默认状态，`blend` 按作品权重分配 |

**简报模板（v0.1.0 定稿）**：

```text
# 创作风格简报｜第 12 章 · 对峙

【总则】克制白描，动作外化情绪；叙述贴着人物，不替他总结。

【这一场】信息后置；对话留潜台词；不要在旁白里给情绪命名。

【写法】
1. 紧张时写手做什么、停在哪、呼吸怎样，不写"他很紧张"。
2. 对话允许答非所问；每三句里至少一句带动作。
3. 段末不要总结，落在动作或物件上。

【不要】眼中闪过一丝 / 空气仿佛凝固 / 不是……而是…… / 段末升华

【语感】「他指尖停在门把上，迟迟没有转动。」（参考 A·第 12 章）

【样段】（你自己的旧作·对峙；学语气，不要搬情节）
「……」（≤400 字，人名已遮蔽）

【硬约束】视角：第三人称限知（林砚）；称呼：林砚→沈砚「沈大人」
```

**六条简报铁律**（验收直接查）：

| # | 铁律 | 违反的样子 |
|---|---|---|
| 1 | 正文 ≤600 字；样段另计 ≤400 字 | 一千字小作文 |
| 2 | 不出现统计数字/百分比 | "短句占 35%" |
| 3 | 每条正条都带"不要……"的边界 | 只有形容词 |
| 4 | 3–5 条正条 + ≤8 条禁条 + 1 条参考锚点（+ 有旧作时 1 段样段） | 20 条规则糊脸 |
| 5 | 锚点与样段优先于通用禁则 | 样段用破折号，却禁破折号 |
| 6 | 硬约束永不被裁掉 | 预算不够先删视角 |

### 5.5 ④ 改之一：检查器 —— 五层，只有第一层"判罪"

```text
L1 可判罪（有位置、误报低、可自动修）    → warn / block
L2 只报（画像，与档案比）               → info
L3 列候选（模型判断，人拍板）            → hint
L4/L5 不检测（语域与优劣是作者的事）      → 不出现
```

**检测器清单（v0.1.0 全部实现）**：

| id | 层 | 判什么 | 怎么判 | 误报 | 输出 |
|---|---|---|---|---|---|
| `negation-parallel` | L1 | "不是 A，而是 B"及其变体 | 正则 + 排除引号内对白 | 中（人物口癖） | warn |
| `paragraph-closure` | L1 | 段末升华 / 解说体（"就这样""从此""他不知道的是""这便是"） | 段尾 30 字内正则 | 低 | warn |
| `emotion-naming` | L1 | 抽象情绪直述（"一种说不出的 X""她感到无比 X"） | 情绪词表 + 句法位置 | 低-中 | warn |
| `cliche-density` | L1 | 套话密度 | 词表命中 ÷ 千字，**按段报，不逐词删** | 低（密度）/ 高（单次） | warn（段级） |
| `overlap` | L1 | 与参考作品 20 字连续重合 | 滚动哈希 | 极低 | **block** |
| `contract` | L1 | 视角 / 称呼 / 知情 / 禁忌（有 fanfic 契约时） | 复用 `GATE_DETECTORS` 思路 | 低 | warn / block |
| `repetition` | L1 | 3-gram 重复、句首 2–4 字重复 | 频次 + 位置 | 中 | warn |
| `rhythm` | L2 | 句长 CV、段长、对话比、标点密度 | 与档案区间比 | **高（题材差异）** | info only |
| `abstraction` | L2 | 抽象名词 / 具体名词比 | 词性启发式 | 高 | info only |
| `explanation` | L2 | 解释性连接词密度（"这意味着/换句话说/于是/所以"） | 计数 ÷ 千字 | 中-高 | info only |
| `triple-parallel` | L3 | 三项排比是否同义 | 模型列候选 | 高 | hint（需签收） |
| `stale-metaphor` | L3 | 比喻是否陈腐 | 模型列候选 | 高 | hint（需签收） |

**findings 结构**（这是给模型和面板的同一个形状）：

```json
{
  "id": "f-003",
  "detector": "emotion-naming",
  "severity": "warn",
  "span": { "start": 1842, "end": 1866 },
  "quote": "她心里涌起一阵说不清的酸楚。",
  "why": "抽象情绪直述：命名了情绪，没有给出可观察的承接。",
  "fix": "换成动作/生理细节，或删掉，让下一句动作接住。",
  "ruleId": "r-012"
}
```

**三条输出纪律：**

1. **不给分**。只给 `block / warn / info` 的条数与位置。面板显示"N 处值得看"，不显示"AI 味 43 分"。
2. **每条必须能定位**。`span.start/end` + 原句；定位不了的不输出。
3. **`rhythm` 永远是 info**。句长齐整可能是古龙，也可能是作者风格；它只配当"画像"，不配当"缺陷"。

**新套话监控（防"清理本身变成新套路"）**：

- 禁语表分三级：`default`（内置，季度重审）/ `book`（本书追加）/ `author`（作者标黑）；
- 每张卡 `ttl` 默认 180 天，到期在"学习"tab 提示重审；
- `voice_polish` 复检时同时检测"本次改写是否引入了上次没见过的套话"，有则整窗回退。

### 5.6 ④ 改之二：定点改写（`voice_polish` 的核心）

**为什么是"定点"**：整篇重写会漂移、会编造、会把好的地方改坏；而且作者无法审。定点改写的每一步都可核对。

```text
1. 选窗     命中 span 向两侧各扩 24 字 → 合并重叠窗 → 单窗 ≤300 字
2. 组上下文 窗口原文 + 命中项(why/fix) + 该场景规则(≤3 条) + 锚点(可选) + 硬约束
3. 生成     模型只输出改写后的「这一段」，JSON { revised }
4. 五道校验  见下表
5. 合并     逐窗替换 → 生成 changes[]（每处：位置、原句、新句、修掉的 detector）
6. 复检     对全文重跑 lint；新增 L1 命中必须为 0
```

**五道校验（任一不过就回退该窗）**：

| # | 校验 | 判据 | 不过怎么办 |
|---|---|---|---|
| V1 | 长度 | 新旧长度差 ≤15% | 回退该窗 |
| V2 | 未命中零改动 | 对齐后未命中区域 diff = 0 | **回退并记 `out-of-scope-edit`** |
| V3 | 不新增事实 | 新数字/新人名/新地名 = 0（对契约与人名表） | 回退（这条最重要） |
| V4 | 不新增习惯 | 该窗复检新增 L1 命中 = 0 | 重试 1 次（降温），仍失败回退 |
| V5 | 不新增重合 | 与参考作品 20 字重合 = 0 | 回退 |

**生成端的三条禁令**（写进 system prompt，且 V2/V3 会兜底）：

> 只改给定片段；不改人名、称呼、数字、时间、视角；不新增任何细节或比喻；不解释人物动机；字数变化不超过 15%。

**参数与预算**：

| 项 | 值 | 理由 |
|---|---|---|
| 单窗字数 | ≤300 | 窗口越大越容易编 |
| 单章窗口数 | ≤20 | 超过说明该章需要人重写，不是修 |
| 轮数 | ≤2 | 第 3 轮开始"改出新的假" |
| 温度 | 0.4（默认）；要出候选时同一窗生成 2 份、温度 0.7 | 低温度降低编造；高一点只用于给作者选项 |
| 单窗 maxTokens | 窗口字数 × 2 + 200 | 防跑题 |
| 失败策略 | 回退原文 + 标 `needs-author` | 宁可不改，不可改坏 |

**候选重排（同一工具的可选模式，零模型）**：当作者/模型手上有 2–3 份稿，`voice_check({action:"rank"})` 用可感知特征距离 + 命中计数 + 锚点重合度算出"谁更接近档案"，输出差异项，**不输出"哪个更好"**。

### 5.7 ⑤ 学：只记录，不升级

v0.1.0 的学习是"记账"，不是"进化"：

| 信号 | 权重（学习策略，不是分数） | v0.1.0 做什么 |
|---|---|---|
| 作者明确改规则（"以后少用成语"） | 极高 | 直接改 Profile + 版本 +1（唯一允许直接写的） |
| 明确点赞/点踩 | 高 | 记事件；同 scope 累计 ≥2 次 → 候选 |
| A/B 选择 | 高 | 记事件（含"比的是哪个维度"） |
| 作者改稿 diff | 低 | 记事件；只做"候选"，不归因 |
| 自然语言意见 | 中 | 记事件；进"待确认" |
| 接受/拒绝草稿 | 中低 | 弱信号，不单独成规则 |

**v0.1.0 不做**：数值自动漂移、候选自动升级、diff 归因、"它学会了"的进度条。理由：一次改稿可能是"这段写得差"，不是"我喜欢这样"；把噪声当偏好，Profile 会漂到作者不想要的地方（v1 §9.1 的判断仍然成立）。

### 5.8 机制成立的四条门槛（不成立就不发版）

| # | 门槛 | 不成立的表现 |
|---|---|---|
| G1 | 人工文本误报 ≤1 处/千字（L1） | 满屏警告，作者关掉插件 |
| G2 | 改写后未命中区域 diff = 0 | "它把我没让它改的地方也改了" |
| G3 | 盲选 ≥7/10 | 作者说"还不如原来" |
| G4 | 零编造（V3 全过） | 出现"她握紧了左手第三根手指"这种凭空细节 |

## 8. 工具、命令与服务

### 8.1 七个工具（比 v1 多一个，理由在下面）

| 工具 | 动作 | 关键参数 | 返回 | 调模型 |
|---|---|---|---|---|
| `voice_import` | `import / list / remove / chapters / preview` | `paths` / `folder` / `sourceType` / `title` / `fixChapters` | `works[]` / `capacity` / `chapters` | 否 |
| `voice_learn` | `measure / sample / analyze / status / cancel / commit` | `workIds` / `mode: local\|quick\|deep` / `budget` | `statistics` / `candidates` / `job` | analyze 时是 |
| `voice_profile` | `list / show / create / confirm / update / weights / rollback` | `profileId` / `patch` / `weights` | `profile` / `versions` | 否 |
| `voice_brief` | — | `book` / `chapter` / `scene` / `cast` / `task` / `budget` / `sampleBudget` | `markdown` / `chars` / `sample` / `rules` / `sources` / `conflicts` | 否 |
| `voice_check` | `lint / rank` | `book` / `chapter` / `text\|path` / `scope` / `candidates[]` | `findings[]` / `portrait` / `deviations[]` / `ranking` | 否 |
| `voice_polish` | `fix` | `book` / `chapter` / `text\|path` / `scene` / `maxRounds` / `maxWindows` / `dryRun` | `revised` / `changes[]` / `before` / `after` | **是** |
| `voice_feedback` | `record / pending / confirm / reject` | `kind` / `text` / `draft` / `final` / `scope` | `candidate` / `pending[]` / `versions` | 否 |

**为什么把 `voice_polish` 独立出来**（v1 只有 6 个工具）：

- `voice_check` 必须**零模型、可离线、可回归**——它是测试与 CI 的基础；
- `voice_polish` 是唯一花钱、唯一会改字的工具，必须能单独关、单独限额、单独审计；
- 两者合在一起，模型会在"只想看看有什么问题"时顺手改稿——这是最危险的一种顺手。

### 8.4 模型调用（本机 DSH 的真实边界）

| 项 | 事实 | 影响 |
|---|---|---|
| 入口 | 只有 `ctx.llm.stream()`，无外部 SDK | 必须显式 `provider` + `model` |
| 采样参数 | **只有 `temperature` / `maxTokens` / `stop`**（本机 `@deepseek-ai/dsh-llm` 明确写了没有 `top_p`、无 penalty） | 不能做 logit bias / 禁 token；只能靠 prompt + 过滤 + 重写 |
| 模型来源 | `ctx.agentDefaultModel.currentSelection()` → `{provider, model}`；插件配置可覆盖 | 解析顺序：配置 > 默认 > `model-unavailable` |
| 用途声明 | `GenerateOptions.purpose` 由 `LlmRequestPurposeMap` 声明；适配器对陌生 purpose 不报错 | 用 `purpose: 'novel-voice'`，并在实现时确认日志形态 |
| 可复现 | `dsh-llm` 的不变式要求"模型可见 ⟺ 可记录" | 请求/响应（含 hash、provider、model、temperature）写 `audit.jsonl`；是否需额外发会话事件，列为开工前待确认项（§13） |
| 失败码 | `NO_ADAPTER` / `MISSING_CREDENTIAL` / `AUTH` / `RATE_LIMIT` / `CONTEXT_WINDOW_EXCEEDED` | 失败即降级纯本地，不伪造技法卡、不伪造改写 |

**成本口径**（写进 UI，别让作者猜）：

| 动作 | 模型调用 | 粗估 |
|---|---|---|
| `measure` | 0 | 0 |
| `sample` | 0 | 0 |
| `analyze` quick | 每作品 4 段 × ≤1,200 字 | 输入 ≈ 5k 字/作品；输出 ≈ 1.5k 字 |
| `analyze` deep | 每作品 12 段 | 输入 ≈ 15k 字/作品 |
| `voice_brief` | 0 | 0 |
| `voice_check` | 0 | 0 |
| `voice_polish` | 每窗 1 次 × 轮数 | 单章典型 3–8 窗；最坏 20 窗 × 2 轮 |

### 9.5 必须砍掉（写进 UI 评审）

| 东西 | 判断 | 理由 |
|---|---|---|
| 文笔评分 / AI 味分数 | 删 | 伪精确，且会诱导"刷分" |
| 作家相似度 / 排行榜 | 删 | 版权伦理 + 与创作无关 |
| 六维统计大屏 | 折叠进详情 | 首屏放不下，也不是决策所需 |
| 模型训练进度条 | 删 | 我们不训练，不能假装有 |
| 全量档案注入 | 禁止 | 上下文爆炸 + 规则打架 |
| 检测器分数 | 禁止 | 验收指标 ≠ 产品指标 |

### 9.6 `meta.description`（插件列表里那段话，定稿）

> 把喜欢的作品放进来，它会提炼你认可的写法：怎么断句、怎么处理对话、什么时候不解释、哪些套话绝对不要。写之前给你一份 600 字的文风简报；如果你的书架里也有你自己的旧稿，它会再附一段你自己写过的段落，让你照着那个呼吸写。写完之后，它把"AI 味"定位到具体的句子，只改那一句，改完证明没动别的地方。它不给你打文风分，也不假装能克隆某位作家——它只做一件事：让写出来的东西更像你，不像一个助手。

### 10.2 最小机制切片（8 个工作日，先做）

**目的**：在写面板之前，先证明"定位 → 定点改写 → 复检"这条链真的能把 AI 味降下去，而且不破坏原文。

```text
M0（1 天，只做 store + 两个工具壳）
+ 内置禁语表 + L1 四个 detector（negation-parallel / paragraph-closure / emotion-naming / cliche-density）
+ overlap（20 字重合）
+ repair（单窗、五道校验、报告）
= 命令行版：`/voice check --path a.txt`、`/voice polish --path a.txt`
```

**用 10 组样本验收**（AI 初稿 → 作者改稿成对，来自作者自己的旧稿与 AI 生成稿）：

- L1 命中下降 ≥60%；
- 未命中区域字符 diff = 0；
- 零编造（数字/专名不变）；
- 作者盲选 ≥7/10。

**过不了就不做面板。** 不是流程主义：面板会把一个不成立的机制包装得很像成立的，之后再想停就难了。

### 11.3 发版门槛（全过才发 0.1.0）

| # | 门槛 | 判据 |
|---|---|---|
| 1 | 检查器可用 | L1 召回 ≥70%；人工段误报 ≤1 处/千字 |
| 2 | 改写安全 | 未命中 diff = 0；编造 = 0；`out-of-scope-edit` 回退率 100% |
| 3 | 改写有效 | L1 命中 ↓≥60%；复检新增 L1 = 0 |
| 4 | 作者认可 | 盲选 ≥7/10 |
| 5 | 简报可用 | 正文 ≤600 字、无数字、3–5 条、1 参考锚点、（有旧作时）1 段 ≤400 字样段、硬约束不裁 |

## 12. 风险与红线

### 12.1 风险排序

| # | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| 1 | 检查器误伤，作者关掉插件 | 极高 | L1 只收四类硬特征；每条可单独关；阈值按书调；info 与 warn 严格分开 |
| 2 | 改写编造细节 | 极高 | V3 硬校验 + 温度 0.4 + 失败回退 + 编造计数进发版门槛 |
| 3 | 为检查器写作（Goodhart） | 极高 | 不给分、不做总数 KPI、禁语表 180 天 TTL、锚点优先于禁则、季度重审 |
| 4 | 机制不成立却包装成成立 | 高 | 8 天切片先验证；门槛 4 不过就退成"只报不改" |
| 5 | 分析成本失控 | 中高 | 全文本地；模型只吃抽样；`local` 默认；后台任务可取消 |
| 6 | 侧栏又打不开 | 中高 | 沿用 fade v0.6 的四步验证：注册 → 打开 → 活树见 occupant → 真点 |
| 7 | 版权与隐私 | 中高 | 本地存储；短引文 ≤80 字；不整本上传；20 字重合检测；不展示作者名（可选） |
| 8 | 与 fanfic 契约漂移 | 中 | 只读；记录契约 revision；不存在时降级为"无契约" |
| 9 | 模型不可用 / 换模型后行为变 | 中 | 失败降级纯本地；审计记录 provider/model；夹具回归可在模型换代后重跑 |
| 10 | 档案膨胀、规则互斥 | 中 | 只编译当前场景；≤5 条规则；冲突表；版本可回滚 |

### 12.2 六条红线

1. **不能无证据建规则**：技法卡的引文必须逐字可回查，找不到就丢。
2. **不能无确认升级**：v0.1.0 的自动学习只产候选。
3. **不能改未命中的地方**：V2 是硬校验，不是提示。
4. **不能编造**：不新增数字、专名、细节、比喻；宁可标 `needs-author`。
5. **不能给分数**：文笔分、AI 味分、相似度分，一个都不出现。
6. **不能把统计写进简报**：统计是尺子，不是笔。

### 15.5 面板与效果图的差距（回答作者的两个问题）

**1. 效果图是情绪板，不是像素稿。** v1 文档已写明：正式 UI 必须用 DSH 主题 token、真实槽位、420px 重做。当前是"第二遍"：卡片、模式色、权重条、技法卡状态条、底部主按钮已按效果图靠。仍不同的地方与时间：

| 项 | 效果图 | 现在 | 什么时候补 |
|---|---|---|---|
| 封面 | AI 插画 | 首字色块 | **不做**（版权与"不诱导模仿作者"），保持色块 |
| 图标 | 成套线性图标 | 手写 SVG 8 个 | 0.2 换成成套图标 |

| 权重 | 可拖 | **已可拖 + 保存**（全局归一化，场景选主模式） | ✅ 0.1.x |

**2. 书架导入入口：原计划 0.2，作者提出后已提前到 0.1.0。** 书架顶部是「来源」分段（参考作品 / 我的旧稿）+ 三个入口：**选文件夹**（宿主 `directoryPicker`，本机 native 已 active，递归导入 TXT/MD）、**选文件**（浏览器读文本后上传，不依赖系统对话框）、**输入路径**（兜底）。三选一，任何一台机器至少有一条能走通。顺带加了「用模板建档案」：书架有作品后，一键统计 + 建档案 + 写入 8 张模板 + 确认，从空书架到能生成简报不用回对话。

### 15.6 下一步

已完成（0.1.x 增量）：

- 面板权重可拖 + 保存；场景主模式可切换；保存时全局归一化。
- 技法卡可展开看原文证据（≤3 条）与反例数。
- **规则挂到模式**：`assignModeRules()` 把 confirmed 规则按 scope 挂到模式上；编译器按"场景权重 × 规则所属模式"加分，权重从此会真的改变【写法】里规则的排序，而不是只改一行"偏克制"。

- **导入编码修正**：浏览器上传改送 base64 原始字节，主机做 UTF-8/GB18030 探测；乱码闸拦下 U+FFFD 比例过高的文本。

- **档案 regenerate**：重建锚点/样段（锚点只取正文、≤60 字），并回填自动总则。
- **简报保底**：L2 节奏规则在 5 条上限里被挤掉过，现在按层留名额。
